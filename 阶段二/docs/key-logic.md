# 关键逻辑说明

## 1. 关键模块与整体流程

第二阶段是在第一阶段问卷系统基础上的增量扩展。第一阶段已经实现用户管理、问卷管理、题目编辑、条件跳转、答案校验、问卷提交和结果统计等功能。第二阶段主要增加题目复用、版本管理、指定用户共享、个人题库和跨问卷统计能力，同时尽量保留原有的数据结构和业务流程。

系统的关键逻辑可以分为以下几个部分：

| 模块 | 主要职责 |
|---|---|
| 题目版本管理 | 管理逻辑题目、版本历史、新版本创建和历史版本恢复 |
| 问卷题目管理 | 将选定版本的内容加入问卷，并维护问卷内的题目配置 |
| 题库与共享管理 | 管理个人题库、指定用户授权、授权撤销和独立副本 |
| 跳转与答案校验 | 根据答题情况计算有效路径，并检查答案是否合法 |
| 使用关系与统计 | 查询题目被哪些问卷使用，并进行跨问卷汇总和版本明细统计 |
| 数据兼容与权限控制 | 保留第一阶段数据，并限制不同用户可以执行的操作 |

这些模块之间存在一定联系。例如，用户从题库选择题目时，需要检查共享权限和版本信息；切换版本时，需要检查问卷配置是否仍然有效；跨问卷统计时，则需要根据题目来源和统计兼容规则筛选数据。因此，第二阶段不是简单地增加几个接口，而是围绕题目身份、版本内容和问卷使用关系，对原有系统进行扩展。

## 2. 题目版本与问卷快照

### 2.1 题目身份与版本内容分离

第二阶段将题目区分为问卷内题目实例、逻辑题目和题目版本三个层次。三者相互关联，但含义和用途不同。

| 标识 | 含义 | 主要用途 |
|---|---|---|
| 问卷内题目实例 ID | 某道题在某份问卷中的具体实例 | 问卷编辑、排序、跳转、答案关联 |
| 逻辑题目 ID | 题目的长期身份 | 题目所有权、版本历史、跨问卷追踪 |
| 题目版本 ID | 逻辑题目的某一份确定内容 | 版本选择、历史查看、恢复和统计分组 |

例如用户将同一道逻辑题目加入两份问卷时，两份问卷中的题目实例 ID 不同，但它们可以关联到同一个逻辑题目和同一个题目版本。如果原题所有者之后修改了题目并创建新版本，原有问卷仍然可以保留之前选用的版本内容。

这种区分既保留了第一阶段通过问卷内题目实例 ID 关联回答和跳转规则的方式，也为第二阶段的题目复用、版本管理和跨问卷统计提供了基础。

### 2.2 问卷题目快照

第二阶段采用题目复用方案：将所选版本的题目内容复制到问卷中，同时保留来源逻辑题目 ID 和来源版本 ID。

例如，用户将 v1 加入问卷 A 后，原题所有者又创建了 v2。问卷 A 仍然保留 v1 对应的题目内容，不会因为题库更新而自动修改。

保留快照的作用有已有问卷的题干、选项和校验规则保持稳定；原有答题、跳转和答案校验逻辑仍然可以直接读取问卷中的题目内容。
这种设计会产生一定的数据冗余，但能够减少对第一阶段代码的改造，也更适合保留历史问卷的原始状态。

### 2.3 题目修改与版本切换

修改题目时，需要区分问卷配置变化和题目内容变化。调整题目顺序、必答设置等问卷配置，不一定意味着来源版本已经改变；修改题干、题型、选项或校验规则，则需要重新确认来源关系。

如果修改后的内容不再与原来源版本一致，就不能继续将其作为原版本的完整快照。用户需要根据权限创建新版本或独立副本，避免来源标识与实际内容不一致。

版本切换应由问卷所有者显式操作，并在切换后检查题目配置和跳转规则。已发布问卷不应因题库中的版本更新而自动改变。

### 2.4 版本恢复与并发修改

题目版本创建后，应保留历史内容。恢复旧版本时，不直接覆盖当前版本，而是创建一个新版本，其内容来自所选择的历史版本。这样可以保留完整的修改过程。

并发修改也需要考虑。例如，两个请求同时基于 v2 创建新版本时，可能分别形成不同的修改结果。版本号较大并不意味着该版本一定包含另一请求的修改。

因此版本编号和当前版本选择应当分开处理。基于过期版本产生的修改可以保留为分支，但不应在未检查当前状态的情况下直接覆盖当前版本。通过预期当前版本或修订号进行检查，可以识别冲突，并由题目所有者决定最终采用哪个版本。

## 3. 题目共享与题库管理

### 3.1 指定用户共享

第二阶段采用指定用户共享方式，由题目所有者选择授权对象。接收者可以在授权范围内将共享题目用于自己的问卷，不需要重新复制粘贴题目内容。

共享使用权不等于题目所有权。原题所有者负责维护原题及其版本；接收者如果需要修改为自己的题目，应创建独立副本，而不是直接修改原题。这种设计适合团队共同制作问卷的场景，也能避免所有用户默认拥有全部题目的使用权限。

### 3.2 多题库管理

每个用户可以创建多个题库，用于按照课程、调查主题或实际用途整理常用题目。题库条目负责组织题目，并可以记录默认使用的版本。

题库与逻辑题目相互独立：删除或移除题库条目，不应直接删除题目版本，也不应影响已经保存到问卷中的快照。

从题库选题时，系统需要检查目标条目、题目版本和当前授权状态。只有满足条件的题目才能被加入问卷。前端显示某道题可用，并不能替代后端的权限检查。

### 3.3 共享撤销与重新授权

撤销共享后，接收者不能再通过原共享关系进行新的选题操作。但此前已经保存的问卷快照、历史回答和合法创建的独立副本应当继续保留。

重新授权时，系统需要重新检查题目状态和授权关系。旧题库条目可以保留，但不能仅凭条目仍然存在，就绕过已经撤销的授权。

此外题目使用权不意味着回答查看权。接收者可以使用授权范围内的题目，但不能因此获得原题所有者或其他用户的问卷管理权限。

## 4. 跳转与答案校验

第二阶段继续保留第一阶段的条件跳转和答案校验机制。跳转规则属于具体问卷中的题目实例，而不是逻辑题目的全局属性，因为同一道题在不同问卷中可能具有不同的后续路径。

### 4.1 条件跳转

系统根据当前问卷的题目顺序、跳转规则和已提交的答案计算答题路径。前端显示的下一题不能作为唯一依据，后端仍然需要判断答案是否符合实际路径。

用户修改前面题目的答案后，后续路径可能发生变化，因此应当清理不再属于有效路径的旧答案，避免不同分支的答案混入最终提交。

### 4.2 答案校验

答案校验由后端执行最终判断。单选题和多选题需要检查所选选项是否有效；文本题需要检查必答和相应限制；数字题需要检查数据类型、数值范围和其他校验规则。

即使前端已经限制了输入，后端也不能直接信任客户端提交的数据。系统还需要检查题目是否属于当前问卷，以及答案是否来自合法的答题路径。

第二阶段增加题目版本和来源关系后，这些检查仍然适用于问卷内的题目快照。来源 ID 的存在不能代替对实际题目内容和答案合法性的检查。

## 5. 题目使用关系与跨问卷统计

### 5.1 题目使用关系

第二阶段需要支持查询某道逻辑题目被哪些问卷使用。系统通过问卷题目实例中保存的来源逻辑题目 ID 和来源版本 ID 追踪使用关系。

查询结果需要区分问卷数量和题目实例数量。使用关系还可以按照版本筛选，以便查看某个版本具体被哪些问卷采用。

查询结果应遵守权限边界。用户可以查看自己拥有的问卷中的使用情况，但不能仅凭题目所有权查看其他用户问卷的完整配置或原始回答。

### 5.2 整体汇总与版本明细

跨问卷统计同时支持整体汇总与版本明细。整体汇总用于了解同一道题在多个问卷中的总体情况；版本明细则用于观察不同版本的数据差异。

两种统计结果需要依据来源关系和兼容配置计算，不能仅凭题目标题相同就直接合并。

对于不兼容的版本，系统应保留分组统计，避免将含义不同的数据放在一起计算。原题所有者可以确认统计兼容关系，但该权限只用于确定统计口径，不自动赋予查看其他用户原始回答的权限。

### 5.3 统计口径与兼容规则

不同题型需要采用不同的统计方式：

| 题型或指标 | 主要统计方式 | 注意事项 |
|---|---|---|
| 单选题 | 各选项的选择次数 | 选项含义需要一致 |
| 多选题 | 分别统计各选项的选择次数 | 各选项次数之和可能超过回答数 |
| 数字题 | 有效答案数量、平均值及分布 | 需要考虑单位、范围和分组边界 |
| 文本题 | 有效回答数量及允许范围内的文本明细 | 需要遵守回答数据的访问权限 |

数字题的平均值应根据所有有效答案的总和与数量计算，不能直接平均不同版本各自的平均值。否则，当不同版本的样本量不同时，结果可能不准确。

统计时还需要明确哪些答案属于有效数据，以及不兼容版本是否应单独展示。对于来源不明确或内容已经脱离原版本的题目，不应自动纳入原题的跨问卷统计。

## 6. 旧数据兼容与数据一致性

第二阶段是在第一阶段代码和数据库基础上进行扩展，因此需要保留原有问卷、回答及其关联方式。

原有问卷继续保存嵌入式题目，回答中的 `questionId` 仍然指向问卷题目实例。新增的逻辑题目和版本关系用于支持后续复用，并不意味着所有历史问卷都必须立即转换为新结构。

对于旧题，可以将其保存到题库以供后续使用，但这一操作不应自动把原问卷的历史回答纳入新的跨问卷统计。

如果需要关联历史回答，应当先确认来源关系、内容一致性和相应权限。不能仅凭题目标题相同，就认定两道题属于同一个逻辑题目。

这一处理方式能够降低升级风险，并尽量保证第一阶段的功能继续可用。不过，部分旧回答可能无法自动参与新统计，需要在测试结果和项目报告中明确说明。

## 7. 关键设计取舍与局限

第二阶段的设计主要围绕历史稳定性、题目复用和权限边界展开。逻辑题目与版本分离便于保留修改历史；问卷快照能够避免题库更新影响已有问卷；独立的共享授权便于管理授权生命周期；来源关系则为题目使用查询和跨问卷统计提供依据。

这些设计也带来了一定代价。快照会增加数据冗余，跨问卷统计需要读取并关联多个集合，版本并发和跨集合操作也比单文档更新更复杂。此外，旧数据来源不明确时，系统不能自动将其合并到新统计中。

因此，第二阶段除了验证新增功能，还需要继续测试第一阶段的跳转、校验、提交和统计等核心流程。只有在新增功能正确、旧功能仍然可用、历史数据得到保留的前提下，才能说明本次升级满足了课程作业的要求。
